# 架构概要

## 总体架构

系统采用 PC Web B/S 架构：前端负责课程、任务、提交、评价和报表可视化；后端负责权限、业务流程、文件解析、智能核查、评分、导出和审计。

## 核心模块

- 用户与权限：管理员、教师、学生三类角色，支持 RBAC。
- Web 工作台：Vue 3 PC Web 入口，支持登录、教师复核队列、AI/规则初评查看、异步任务状态、审计日志和报表导出入口。
- 实训管理：课程、班级、实训任务、提交截止时间、评价模板和指标权重。
- 成果管理：提交记录、文件上传、本地 ObjectStore、解析任务、解析结果和失败状态。
- 异步任务：PostgreSQL jobs 队列、`FOR UPDATE SKIP LOCKED` 并发领取、失败重试和 stale job 释放。
- 运行治理：教师/管理员任务状态查询、审计日志筛选和失败任务排障。
- LLM Gateway：统一 OpenAI-compatible HTTP 调用，支持云端和本地/局域网服务，业务模块不直接依赖模型 SDK。
- 初评生成：规则核查、脱敏证据摘要、JSON 输出校验、AI 草稿落库、教师复核入口。
- 智能核查：确定性规则核查 + LLM 初评，输出需求覆盖、步骤完整性、证据质量、扣分点、置信度和风险标签。
- 教师复核：逐项改分、评语、最终确认、结果发布和学生已发布反馈查看。
- 报表导出：学生个人报告、班级统计、课程统计、异步 Excel/PDF 生成和对象存储落盘。
- 审计与日志：上传、解析、LLM 调用、教师改分、结果发布、报表导出全链路留痕。

## 数据流

1. 学生提交成果文件或 Git 链接。
2. 后端校验文件类型/大小，将文件保存到 `STORAGE_ROOT`，写入 `artifacts` 元数据并创建 `parse_artifact` 任务。
3. 上传动作写入审计日志，教师可通过任务状态接口跟踪解析进度。
4. 解析器提取文本、截图 OCR、代码结构和元数据，并写入成功/失败审计事件。
5. 解析全部完成后创建 `evaluate_submission` 任务，评价 worker 构建脱敏证据摘要。
6. 规则引擎执行确定性核查，写入指标 `rule_score` 与需求/步骤/文档/逻辑/安全发现。
7. LLM Gateway 发送脱敏摘要和证据片段，JSON 输出通过后端校验后写入 AI 初评。
8. 教师复核并确认最终成绩，再发布给学生。
9. 学生只能查看本人已发布反馈，未发布评价仍保留在教师端。
10. 管理员/教师创建 `export_report` 任务，报表 worker 读取已发布评价统计并生成 Excel/PDF 写入对象存储。
11. Web 工作台通过 `VITE_API_BASE_URL` 调用 API，所有业务接口携带 Bearer Token；页面必须处理未登录、API 不可用和空数据状态，便于跨 amd64 开发环境与 LoongArch 目标环境调试。

## 关键约束

- LLM 只能作为初评辅助，最终成绩必须留有教师确认或系统发布记录。
- 教师复核、发布和学生反馈读取必须写入审计或受 RBAC/学生归属限制保护。
- 云端模型默认不接收原始文件，只接收脱敏摘要和必要证据片段。
- 未配置 LLM 时不得阻塞主流程，应生成教师待复核草稿并记录跳过原因。
- 文件解析能力必须可降级，目标环境缺少依赖时进入人工确认流程。
- 高并发上传不得同步执行重解析；API 入队后由多个 worker 横向消费，详见 `docs/CONCURRENCY.md`。
- 报表只统计已发布评价；未发布 AI 草稿和教师复核中数据不会进入学生/课程正式报表。
- 前端不得直接访问对象存储路径；导出文件下载需后端提供受 RBAC 保护的下载接口后再开放。
